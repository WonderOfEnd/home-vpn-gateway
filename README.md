# home-vpn-gateway

Домашний сервер с Debian может быть VPN-шлюзом для компьютеров, телефонов и
телевизора. Устройства получают шлюз и DNS от роутера, Xray отправляет выбранный
трафик на зарубежный VPS, а Pi-hole фильтрует DNS. Приложения VPN на устройствах
домашней сети для этого не нужны.

<a id="install-home"></a>
## Как установить у себя дома

### Что понадобится

| Что | Что выбрать для первого запуска |
| --- | --- |
| **VPS за границей** | Debian, постоянный публичный IPv4, доступ администратора по SSH. Стартовый ориентир для одной семьи — 1 vCPU, 1 ГБ ОЗУ и 10 ГБ диска. Для видео и загрузок учитывайте скорость канала и месячный лимит трафика. Подойдёт и уже работающая ссылка VLESS + REALITY с транспортом TCP. |
| **Сервер дома** | Мини-ПК, одноплатный компьютер или ВМ с чистым **Debian 13**, архитектура amd64 или arm64. Для начала — 1 ядро, 1 ГБ ОЗУ и 8 ГБ диска. С запасом для Docker, журналов и списков фильтрации — 2 ГБ ОЗУ и 16 ГБ диска. Один Ethernet-порт до роутера. Для ВМ выберите сетевой мост (bridge), чтобы роутер видел её как отдельное устройство. |
| **Роутер** | Для всей сети нужен доступ к настройкам **LAN → DHCP** с полями «Основной шлюз» (option 3) и «DNS-сервер» (option 6). Если роутер позволяет задать только DNS, шлюз и DNS можно указать вручную на нужных устройствах. Публичный IP и проброс портов **дома** не требуются. |

Эти характеристики — ориентиры для выбора оборудования. Скорость туннеля
зависит от процессоров, домашнего канала и маршрута до VPS. [Требования самой Pi-hole](https://docs.pi-hole.net/main/prerequisites/).

### 1. Получите ссылку на VPS

Если у вас уже есть рабочая клиентская ссылка `vless://` с **RAW/TCP + REALITY**,
переходите к шагу 2. Мастер понимает профиль с пустым Flow и с `xtls-rprx-vision`.

1. На новом VPS разрешите входящий **TCP 443** для VPN и **TCP 80** для выпуска и продления сертификата панели. Сделайте это в сетевом экране провайдера и в firewall сервера, сохранив доступ по SSH. Подключитесь к **VPS** по SSH и выполните от root команды ниже. При установке 3X-UI выберите SQLite и сертификат **Let's Encrypt для IP**. Собственный домен для этого не нужен. Сохраните выданные адрес панели, логин и пароль. [Установка 3X-UI](https://github.com/MHSanaei/3x-ui/tree/v3.11.0#quick-start).

   ```sh
   apt-get update && apt-get install -y ca-certificates curl
   curl -fL https://raw.githubusercontent.com/MHSanaei/3x-ui/v3.11.0/install.sh -o /root/install-3x-ui.sh
   bash /root/install-3x-ui.sh v3.11.0
   ```

2. Откройте адрес панели, который напечатал установщик. Доступ к её административному порту в firewall разрешите со своего IP. В разделе **Inbounds / Входящие → Добавить** укажите **VLESS**, порт **443**, транспорт **TCP (RAW)**, защиту **REALITY**. Поле шифрования VLESS оставьте **none**. Если такой вход уже есть, откройте его и добавьте отдельного клиента.
3. Для нового входа укажите **Target** (например, `www.microsoft.com:443`) и соответствующий **SNI / Server Names** (`www.microsoft.com`). Сайт должен быть доступен с VPS. Сгенерируйте пару ключей и Short ID кнопками панели. Добавьте клиента, например `home-gateway`, оставьте созданный UUID, выберите Flow `xtls-rprx-vision` и сохраните. [Параметры REALITY в 3X-UI](https://github.com/MHSanaei/3x-ui/blob/v3.11.0/docs/content/docs/en/config/reality.mdx).
4. У клиента нажмите **Копировать ссылку**. В адресе подключения должен быть публичный IPv4 VPS или его домен с одной A-записью. По возможности проверьте ссылку в VPN-приложении телефона через мобильный интернет. Ссылка даёт доступ к вашему VPS через VPN, храните её как пароль.

### 2. Запустите мастер на домашнем сервере

Установите [Debian 13](https://www.debian.org/distrib/netinst) без графического
рабочего стола. Выберите постоянный свободный IPv4 домашнего сервера в сети роутера.
Например, если роутер — `192.168.1.1/24`, серверу можно дать `192.168.1.10/24`
вне пула DHCP. При ручной настройке сети Debian задайте серверу шлюз и DNS
роутера (`192.168.1.1` в примере). Если вместо статической настройки используете
резервирование по MAC, роутер должен продолжать выдавать **самому серверу**
исходный шлюз и рабочий DNS после изменения DHCP для остальных устройств.

Выполните эти команды в терминале **домашнего Debian**.

```sh
sudo apt-get update && sudo apt-get install -y git python3 iproute2 ca-certificates
git clone --depth 1 https://github.com/WonderOfEnd/home-vpn-gateway.git
cd home-vpn-gateway
sudo python3 install.py
```

Если вы вошли как root, команды выполняются без `sudo`. Мастер покажет найденный
интерфейс, IP и роутер. Вставьте ссылку и нажмите Enter — при вводе символы
скрыты. Проверьте адреса и введите `да`. Для предварительного просмотра есть
`python3 install.py --plan`. Мастер устанавливает Xray, Docker с Pi-hole и
`home-net`, проверяет туннель и DNS, затем включает маршрутизацию и её автозапуск.
На сервере с уже настроенными сервисами используйте отдельную ВМ.
Для доменного адреса мастер сохранит текущий IPv4 VPS. Если провайдер позже
сменит этот адрес, потребуется обновить настройки шлюза.

### 3. Проверьте одно устройство, затем подключите семью

1. Запишите текущие настройки DHCP роутера. На **одном** компьютере в домашней сети сохраните его собственный IPv4 и маску, а в поля **шлюз** и **DNS** впишите IP домашнего сервера, который напечатал мастер. В примере оба поля — `192.168.1.10`.
2. На этом компьютере отключите его собственный VPN. Запрос `nslookup example.com 192.168.1.10` должен вернуть адрес. Откройте [проверку внешнего IPv4](https://api.ipify.org) и сравните с `curl -4 https://api.ipify.org` на VPS. На домашнем сервере `home-net status` должен показать работающий туннель и DNS. Панель Pi-hole находится по адресу `http://192.168.1.10:8080/admin/`, пароль доступен на сервере через `sudo cat /opt/home-vpn-gateway/private/.env`.
3. Когда тест прошёл, в настройках **LAN → DHCP** роутера задайте этот IP как шлюз и единственный DNS для клиентов. Сохраните и переподключите устройства к Wi-Fi или обновите аренду DHCP. На тестовом компьютере можно вернуть автоматическое получение адреса. Настройки подключения роутера к провайдеру (WAN) для этого не нужны.

Шлюз управляет **IPv4**. Российские и локальные назначения идут напрямую, остальной
TCP и DNS через Pi-hole — по правилам Xray. Обычный UDP идёт напрямую, для
TruckersMP есть отдельные правила. Если роутер раздаёт IPv6, устройства могут
выходить через провайдера по IPv6. Для сети, где нужен только описанный маршрут,
отключите выдачу IPv6/RA клиентам. Собственный зашифрованный DNS браузера
обходит фильтрацию Pi-hole.

### Если интернет пропал

- Проверить шлюз — `home-net status`. Попробовать восстановить туннель — `sudo home-net fix`. Временно дать устройствам прямой интернет и DNS — `sudo home-net direct`, вернуться к VPN — `sudo home-net vpn`.
- Если домашний сервер выключен или вы хотите отказаться от шлюза, верните прежние шлюз и DNS на роутере и тестовом устройстве, обновите DHCP. После этого удалить установку можно командой `sudo python3 /opt/home-vpn-gateway/install.py --uninstall`. Мастер снимет свои правила, отключит свои службы и сохранит конфиги и данные Pi-hole в закрытом каталоге `/opt/home-vpn-gateway.backup-…`. Установленные пакеты Debian и Docker останутся.
- По желанию включите `sudo systemctl enable --now home-net-watchdog.timer`: после четырёх неудачных проверок он переключит сеть на **прямой интернет**, после четырёх успешных вернёт VPN. Голосовой маршрут Discord для выбранного ПК, веб-интерфейс исключений и личные уведомления настраиваются отдельно.

## Действующая конфигурация home

Репозиторий также хранит исходную конфигурацию домашнего сервера `home`.
[История и результат сверки](docs/audit-2026-10-31.md).

При сбое интернета: `ssh home home-net fix`. Проверка состояния:
`ssh home home-net status`. [Утилита home-net, аварийный прямой режим и установка](home-net/README.md).

Автозащита проверяет связь каждые 30 секунд: четыре неудачи подряд включают
прямой интернет, четыре успешные проверки VPN подряд возвращают VPN и Pi-hole.
[Разбор сбоя и проверки 13 ноября 2026](docs/incident-2026-11-13.md).

Адрес внешнего VPN-сервера, UUID клиента, ключ REALITY и MAC клиента LAN
заменены параметрами. Пароли, ключи доступа и локальные базы Pi-hole в Git
не сохраняются. Настройки внешнего VPN-сервера — отдельная предпосылка установки.

## Структура

| Путь | Назначение |
| --- | --- |
| `xray/config.json` | Обезличенный актуальный конфиг клиента Xray |
| `iptables/rules.txt` | Снимок IPv4-правил в формате iptables-restore |
| `systemd/`, `scripts/` | Xray, policy routing, исключения и правило Discord |
| `discord/` | Пример параметров MAC и LAN-интерфейса |
| `exceptions/` | Существующий LAN-интерфейс исключений сайтов |
| `pihole/`, `sysctl/` | Настройки DNS, Compose template и IPv4 forwarding |

## Маршрутизация

- На роутере DHCP-шлюз и DNS указывают на домашний сервер.
- DNS из LAN перенаправляется в Pi-hole. Единственный upstream —
  `127.0.0.1#5353`: Xray передаёт запросы через туннель.
- TCP из LAN поступает в `redirect-in` на порту 12345. Приватные адреса,
  российские назначения и пользовательские исключения идут напрямую;
  остальные соединения — через `proxy`.
- Обычный UDP остаётся прямым. Для четырёх адресов TruckersMP сохранён
  перехват через `XRAY_UDP`.
- Голос и трансляции нативного Discord выбранного ПК распознаются отдельным
  правилом и передаются в UDP-inbound Xray на порту 12346.
- Существующее правило FORWARD блокирует UDP 443 из LAN. Соединения приложений,
  способных повторить запрос по TCP, затем проходят обычный TCP-маршрут.

## Восстановление исходного сервера home

Следующие шаги относятся к восстановлению прежней установки из её копий.
Для нового сервера используйте [мастер установки](#install-home).

1. Установить Xray с geodata, Docker, sudo, iptables-persistent и Pi-hole.
2. В копии `xray/config.json` заполнить `<VPS_IP>`, `<CLIENT_UUID>`,
   `<REALITY_SERVER_NAME>`, `<REALITY_PUBLIC_KEY>`, `<REALITY_SHORT_ID>` из своей
   панели x-ui. Используется отдельный VLESS/REALITY клиент на TCP 443 без flow.
   Проверить подготовленный конфиг через `xray run -test`.
3. Установить `systemd/xray.service`, его drop-in и две службы
   `xray-tproxy-*.service` в соответствующие пути `/etc/systemd/system/`.
4. Установить `scripts/xray-tproxy-rules.sh` в `/usr/local/bin/` с режимом 755.
   Этот скрипт восстанавливает fwmark 1 / table 100, предварительно убирая
   старое правило и содержимое данной таблицы.
5. В копии `iptables/rules.txt` заполнить `<VPS_IP>` и проверить имя LAN-интерфейса
   (`enp2s0` в снимке). Это полный снимок таблиц, включая существовавшие Docker
   chains и повторяющиеся live rules. Перед применением сохранить текущие правила.
6. Применить подготовленный файл через iptables-restore и сохранить средствами
   netfilter-persistent. Не загружать параллельно конкурирующий набор nftables.
7. Установить `sysctl/90-home-vpn-gateway.conf` в `/etc/sysctl.d/`, применить sysctl.
8. Выполнить daemon-reload, включить Xray и две службы policy routing.
9. Восстановить Pi-hole по [его настройкам](pihole/NOTES.md), затем DHCP шлюза/DNS.

Основной outbound `proxy` использует Mux: `concurrency: 256`,
`xudpConcurrency: 128`, `xudpProxyUDP443: allow`. Дополнительный `proxy-voice`
сохранён из live config, но текущие routing rules его не выбирают.

## Голос Discord

31 октября прямой UDP к назначенному голосовому серверу не отвечал, хотя
управляющее WebSocket-соединение работало. Через Xray получен корректный ответ
за 72–73 мс. Подтверждены RTC_CONNECTED голоса и трансляции; владелец подтвердил звук.

Правило использует [формат IP Discovery нативного Discord](https://docs.discord.com/developers/topics/voice-connections#ip-discovery):
UDP payload 74 байта, type 1, length 70. Для исходящих пакетов выбранного MAC
ставится conntrack mark `0x40000000`. Весь такой поток направляется TPROXY на
`127.0.0.1:12346`. IP голосовых серверов не фиксируются. Область работы — IPv4
и нативный клиент; браузерный WebRTC использует другой handshake.

Восстановление правила:

1. Установить `scripts/discord-voice-route.sh` в `/usr/local/bin/` с режимом 755.
2. Скопировать `discord/discord-voice-route.env.example` в
   `/etc/default/discord-voice-route`, задать реальные PC_MAC и LAN_IFACE.
3. В `systemd/discord-voice-route.service` заполнить USER и GROUP placeholders.
   На проверенном home у выбранного пользователя уже разрешён NOPASSWD-запуск
   `/usr/sbin/iptables`. Шаблон службы сам таких разрешений не создаёт.
4. Установить службу, выполнить daemon-reload и
   `systemctl enable --now discord-voice-route.service`.

Служба запускается после Xray, policy routing и netfilter-persistent;
перезапуск netfilter-persistent переустанавливает правило. Discord chain
исключена из статического rules.txt, поскольку ею управляет служба.

Проверка: `systemctl status discord-voice-route` и
`iptables -t mangle -L DISCORD_VOICE -n -v`. Откат: остановить и отключить
discord-voice-route.service; ExecStop удаляет только её собственную цепочку и hook.

## Исключения и журналы

LAN UI исключений работает на порту 8090 с HTTP Basic Auth. Домены хранятся
в `/etc/xray-exceptions.json`, пароль — в отдельном локальном файле. Для новой
установки список начинается с `[]`; личные исключения в шаблон не копировались.

С 27 октября у Xray `access: none`, `loglevel: warning`: журнал соединений
отключён, ошибки продолжают сохраняться в `/var/log/xray/error.log`.
Логирование Pi-hole этой правкой не менялось.
