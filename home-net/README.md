# home-net

Быстрое восстановление интернета через домашний шлюз без изменения DHCP,
шлюза и DNS на роутере. Утилита предназначена для этого IPv4-шлюза:
Xray SOCKS на `127.0.0.1:10808`, DNS на `127.0.0.1:53`,
LAN по умолчанию `enp2s0`, `192.168.0.0/24`.

## Команды

С компьютера администратора:

```sh
ssh home home-net status
ssh home home-net fix
ssh home home-net direct
ssh home home-net vpn
```

- `status` проверяет HTTPS через Xray и ответ DNS, показывает текущий режим.
- `fix` при исправной связи ничего не перезапускает. При сбое один раз
  перезапускает Xray и повторяет проверку. Если VPN/DNS не восстановились,
  включает прямой интернет. Если уже включён прямой режим и VPN заработал,
  возвращает обычный режим с проверкой DNS.
- `direct` включает прямой IPv4-интернет и прямой DNS через резервный
  резолвер. Перехват Xray и фильтрация Pi-hole временно обходятся.
  Для заблокированных ресурсов нужен отдельный VPN на устройстве.
- `vpn` проверяет туннель, при необходимости один раз перезапускает Xray
  и возвращает обычный режим. При неудаче текущий режим сохраняется.
  Если после возврата не отвечает DNS, прямой режим включается обратно.

Режим сохраняется после перезагрузки через включение/отключение
`home-gateway-direct.service`. Проверки используют два HTTPS-сайта
и обычный DNS-запрос; это проверка работоспособности, а не полная диагностика
провайдера или удалённого сервера.

Переключение NAT действует на новые соединения. Уже открытые соединения
могут временно сохранить предыдущий маршрут; при необходимости обновите
страницу или переподключите приложение.

## Автоматическая защита

Дополнительный `home-net-watchdog.timer` запускает проверку каждые 30 секунд.
После четырёх неудачных проверок подряд (примерно две минуты) он включает
прямой интернет. Сбой VPN или DNS обычного режима считается неудачей.
В прямом режиме проверки VPN продолжаются с тем же интервалом: четыре
успешных результата подряд возвращают VPN и фильтрацию Pi-hole.
Один противоположный результат сбрасывает текущую серию. После каждого
переключения начинается новая серия; цикл повторяется постоянно.

VPN проверяется реальными HTTPS-запросами через Xray даже в прямом режиме.
Перед окончательным возвратом проверяется DNS обычного режима: при сбое
включается прямой интернет и начинается новая серия проверок VPN.
Таймер не перезапускает Xray. Ручная команда `home-net fix` сохраняет своё
поведение с одной попыткой перезапуска.

Автопереключение включается отдельно:

```sh
sudo systemctl enable --now home-net-watchdog.timer
```

В аварийном режиме интернет и DNS идут напрямую, без туннеля и фильтрации
Pi-hole. Сам установщик таймер не включает. Для обслуживания Xray автоматическую
защиту можно остановить: `sudo systemctl disable --now home-net-watchdog.timer`.
Это также нужно, чтобы оставить ручной прямой режим без автоматического возврата.
Счётчики хранятся в `/run` и сбрасываются после смены режима, перезагрузки или
перерыва между проверками больше 75 секунд. Журнал содержит сбои, серии
восстановления VPN и попытки переключения.

## Установка

### Личные уведомления на Android

Отдельный `home-net-notify.timer` наблюдает режим шлюза каждые 15 секунд.
Смена на прямой интернет или обратно в VPN создаёт одно уведомление в ntfy.
Это не дополнительная проверка VPN и не влияет на цикл 30 секунд / 4 результата.
Ручные переключения также замечаются. Первое наблюдение после установки
задаёт исходный режим без ложного уведомления о переключении.

Нужен `dig` (в Debian пакет `bind9-dnsutils`) и случайное имя темы ntfy.
Бесплатная тема на `ntfy.sh` доступна всем, кто знает её имя, поэтому имя
нельзя добавлять в Git или журналы. Отправляются только режим и время события.

```sh
sudo install -d -m 700 /etc/home-net
sudo install -m 600 home-net/ntfy.json.example /etc/home-net/ntfy.json
sudoedit /etc/home-net/ntfy.json
sudo systemctl enable --now home-net-notify.timer
sudo /usr/local/libexec/home-net-notify.py --test
```

В `/etc/home-net/ntfy.json` замените пример на длинное случайное имя темы,
затем подпишитесь на эту тему в приложении ntfy с сервером `https://ntfy.sh`.
В Android разрешите уведомления; для быстрой доставки можно включить
Instant delivery и разрешить приложению работу без ограничений батареи.

Доставка использует прямое HTTPS-соединение с проверкой сертификата и
отдельный DNS-запрос к `1.1.1.1`, без SOCKS и системных настроек прокси.
Событие сначала сохраняется в `/var/lib/home-net-notify/state.json` с доступом
только root. При недоступности сети оно остаётся в очереди; таймер повторяет
отправку раз в 15 секунд, по одному событию за запуск. В сообщении сохраняется
исходное время, поэтому запоздавшее уведомление можно отличить от нового.
При потере ответа сервера после отправки возможен повтор уведомления.
Если сам home выключен, отправка и наблюдение недоступны.

### Установка утилит

Нужны Python 3, curl, iptables, sudo и systemd. Нужна уже настроенная обычная
маршрутизация LAN через шлюз с IPv4 forwarding и masquerading.

```sh
sudo bash home-net/install.sh
sudoedit /etc/default/home-gateway-direct
home-net status
```

Установщик не меняет текущий сетевой режим и права sudo. На рабочем home
администратору уже разрешён беспарольный `systemctl`. Для другой установки
можно настроить только три необходимые команды по `sudoers.example`
через `visudo`.

Перед обновлением утилиты нужно вернуться в VPN-режим. Перед изменением
LAN-интерфейса, подсети или DNS в `/etc/default/home-gateway-direct`
следует выключить прямой режим, затем применить новые настройки.

## Правила аварийного режима

Служба управляет только собственными цепочками `HG_DIRECT_*` и их hook rules.
Она не очищает остальные таблицы и не меняет существующие настройки Xray,
Pi-hole, Docker или VPN-учётные данные. При включении:

- DNS от LAN и локальные запросы к DNS шлюза перенаправляются на публичный
  резервный DNS, по умолчанию `1.1.1.1`, по UDP и TCP.
- Для интернет-трафика LAN обходятся TCP redirect, UDP TPROXY и запрет QUIC.
- Доступ к локальным сервисам, приватным сетям и опубликованным Docker-портам
  проходит по существующим правилам.

При отключении удаляются только созданные утилитой правила. Не следует
сохранять аварийные цепочки через `netfilter-persistent save`:
их восстанавливает отдельная служба после загрузки обычных правил.

Если сам home выключен или недоступен по LAN, команда на нём не выполнится.
В этом случае на роутере остаётся аварийный вариант: убрать home из DHCP-шлюза
и DNS и использовать прямой интернет/запасной VPN на устройствах.
После восстановления home вернуть DHCP-шлюз и DNS `192.168.0.2`.
